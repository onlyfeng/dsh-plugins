# 项目开放 MR

在 DSH Desktop 会话右侧栏的「开始」页打开「项目开放 MR」，即可浏览当前检出项目作为目标项目的开放合并请求。源分支可以位于同一项目，也可以来自 fork。点选「加入会话」后，在官方「代码审查和变更」面板查看 MR 的状态、diff 和讨论。

## 安装和使用

适用于 DSH Desktop `0.2.2-rc.5`。先启用「变更请求与工作树」并配置可识别自建实例的 GitLab forge provider。本机 `glab` 需要已登录并拥有项目读取权限。在 Desktop 插件市场选择 `@onlyfeng/dsh-forge-gitlab-project` 的稳定版本，核对 Git 来源后安装并启用。

1. 在目标 GitLab 检出下的会话中打开右侧栏的「项目开放 MR」。
2. 按更新时间翻页查看开放 MR。每页最多 25 条，最多读取 20 页。需要查看最新状态时点刷新。
3. 对选中的 MR 点「加入会话」。插件重新核对会话、项目与 MR 的开放状态，关联后会话可使用官方变更请求面板。

项目由当前会话的 Git 检出和已注册的 forge provider 确定。绑定记录保存在该会话中。已有绑定可在官方面板使用「从本会话移除」和「撤销」。如果官方面板提示无法读取 Git，请先查看该提示的具体原因，确认会话具有读取检出信息的权限。

## 数据与运行环境

本插件通过 `glab api --method GET` 读取项目元数据和 MR 摘要，认证由本机 CLI 管理。展示和关联均通过 Desktop 的会话命令执行，列表中的项目路径、标题、分支、作者和链接会进入该会话的命令结果记录。列表只在打开、刷新或翻页时读取；关联动作只写入本机 DSH 会话。

包内的 `glab-read.js` 取自同仓库 GitLab reader 的 `0.1.1` 只读传输，可以与该稳定版配合使用。使用其他 `glab` 安装位置时，请保证 Desktop 启动环境的 PATH 能找到该 CLI。
